# Stuntman Chris — build plan & module contract

Status: **v1 = off-chain, dummy RNG, direct-link only** (`/games/stuntman-chris`). Not in GameSummaries until on-chain.

Raw art: `public/images/games/meebel-knievel/` (1.8GB, read-only source — must never ship/commit).
Runtime assets: `public/images/games/stuntman-chris/` generated by `scripts/build-stuntman-chris-assets.ts`.

## Game concept

Launch-and-fly distance game (Toss the Turtle / Learn to Fly genre):

1. Chris idles on his motorbike on a city road at dusk (looping parallax scene).
2. Player charges the **power meter** (hold the Power button / spacebar) and releases to go.
3. Chris rides (idle→transition→riding anim), accelerates toward the crashed, electrified **UFO ramp**, and launches into the sky (flying anim).
4. Flight phase: the world scrolls by (parallax), a **distance counter (m)** climbs. Scripted events fire:
   - **Lasers** shoot up at him — near-misses are flavor; a scripted hit plays the `chrisDeathLaser` anim and ends the run.
   - **Skeleton obstacles** (in graves) throw bones — a scripted bone hit ends the run.
   - **Bounce objects** (crashed UFOs / meebit bystanders / trampoline-like set pieces): landing on one bounces Chris up with a speed boost.
   - **Moonboots powerup**: pickup grants a boost.
5. Run ends by death event or by decelerating to a landing. Result overlay shows distance (+ session best). Back to idle.

## Determinism model (the on-chain seam)

**Outcome-first, playback-second** — same pattern as our other games (contract decides, animation realizes):

- `generateFlightPlan(rng, params) → FlightPlan` — pure function. v1 feeds it `Math.random`-based rng; on-chain v2 feeds VRF-derived values. Nothing else changes.
- `FlightPlan = { finalDistance, endCause: 'laser' | 'bone' | 'landed', events: FlightEvent[] }` where events are keyed by world distance (`atX`), e.g. `{ kind: 'bounce' | 'laserMiss' | 'laserHit' | 'skeleton' | 'boneHit' | 'moonboots', atX, ... }`.
- The engine simulates kinematics that **exactly realize** the plan: piecewise ballistic arcs, bounces at scripted points, death at scripted point, glide-out so the run ends at `finalDistance`. The plan is authoritative; physics is presentation.

## Engine (pure TS, no React/DOM) — `components/games/stuntman-chris/lib/engine/`

State machine phases:

`loading → title → ready → charging → riding → launching → flying → dying | landing → ended`

- `class StuntEngine { start(plan, power); tick(dtMs): EngineState; }`
- `EngineState` (read every frame by renderer): `{ phase, x /* meters */, y /* altitude m */, vx, vy, powerFrac, distanceShown, activeEvents /* nearby world objects w/ positions & anim clocks */, chrisAnim: { key, t }, cameraX }`
- World coords in meters; ground `y=0`. Tuning constants in one `TUNING` object (launch speed from power, gravity, bounce restitution+boost, laser cadence, px-per-meter).
- Chris anim selection is engine-owned (idle/transition/riding/flying/death), renderer just plays what it's told (same split as The Cube: engine owns truth, renderer animates).

## Renderer (canvas 2D) — `components/games/stuntman-chris/lib/render/`

- Fixed internal resolution 1920×1080, scaled to fit container (letterbox), `image-rendering` default (art is pre-antialiased pixel style).
- `SpritePlayer`: takes `SpriteSheetMeta` (from `assets.generated.ts`) + loaded image → `draw(ctx, tMs, dx, dy, scale)`. Handles grid frames, loop vs clamp, and trim-offset registration (`trimX/trimY/scale/srcCanvas*` restore original 1023×1023 anchoring).
- Parallax: `background` ×0.10, `midground` ×0.35, `foreground` ×1.0 scroll factors; each layer drawn twice with modulo wrap (art loops seamlessly). Scroll px = `cameraX * pxPerMeter * factor`.
- Camera: Chris pinned at ~30% screen x during flight; altitude mapped so high arcs stay in frame (mild vertical camera or scale-out — keep simple: clamp + follow y).
- World objects (skeletons, ramp, bounce items, moonboots) placed at plan `atX` positions, drawn when within camera range; skeleton + bone sheets composited separately (bone = projectile).
- rAF loop lives in the scene component; engine `tick` then `render`, no React state per frame (refs only) — React state only for phase transitions/HUD.

## Page/UI — `components/games/stuntman-chris/` + `app/games/stuntman-chris/page.tsx`

- Tiny server-component route page mounting the client orchestrator, per the conventions section below.
- Title screen: `start-screen.mp4` loop (poster fallback), title logo, "tap/space to start"; instruction overlay (`instructionBg`) on first visit.
- HUD: distance counter (big, top), session-best, power meter (60/30-frame sheet) + power button during charge.
- Result overlay: distance, cause of end (crashed vs landed), play-again. Dummy mode: **no bets/APE anywhere yet** — visual test build.
- Preloader: load all sheets before leaving title (progress bar); assets total ~15–20MB.
- Mobile: same 16:9 canvas scaled; portrait shows the scene letterboxed with controls below (match how our other canvas games handle it).
- Sound: none in v1 unless assets exist (there are none) — leave the seam.

## Codebase conventions (from exploration — binding)

- **Read `docs/game-porting-guide.md` first** — this build is exactly its "dummy RNG port" phase. Hard rules: never modify shared components (`GameWindow`, `GameResultsModal`, `SpriteAnimation`, `BetAmountInput`, `context/*`, `hooks/*`, `lib/*` outside our game), no new deps, don't add to `GameSummaries`, don't wire a contract.
- **Code lives in `components/games/stuntman-chris/`** (NOT app/). Route `app/games/stuntman-chris/page.tsx` is the tiny server-component template (copy `app/games/the-cube/page.tsx` shape).
- Registry: add `export const stuntmanChrisGame: SimpleGame` to `lib/constants/games.ts` — `id: 42`, `type: "plinko"` (category hint; crash/arcade precedent), `url: "/games/stuntman-chris"`, placeholder `gameAddress: "0x0000000000000000000000000000000000000004"`. Add the `GameSummaries` block **commented out** with a go-live comment (dojo-drop idiom).
- Window chrome: **`FluidGameWindow`** (`components/games/shared/FluidGameWindow.tsx`) — our scene is 16:9 and `GameWindow`+`skipDefaultBackground` forces `aspect-square`. We draw our own frame; no shared results modal (no bets in v1 anyway). Right rail = `StuntmanChrisSetupCard` sibling in the standard `flex flex-col lg:flex-row gap-4 sm:gap-8 lg:gap-10` shell, window side `lg:basis-2/3`, page container `w-full max-w-6xl mx-auto`.
- Scene sizing: aspect-ratio box + ResizeObserver pattern from `components/games/shared/physics-plinko/PhysicsPlinkoBoard.tsx:415-430`, `aspectRatio: "16 / 9"`, `touchAction: "manipulation"`; DPR canvas recipe from `components/games/dojo-drop/GameCanvas.tsx:355-382`. No orientation lock (none exists in the codebase).
- Renderer mounting: dynamic-import inside `useEffect` island — copy `components/games/ghost-machine/GhostMachineWindow.tsx` (SSR-safe, `dispose()` on cleanup, prefs pushed via a separate light effect).
- Preload: blocking overlay pattern from `components/games/pop-n-drop/PopNDropPreloadOverlay.tsx` (module-scoped `hasEverPreloaded`, per-asset timeout, `z-[80]`).
- i18n: **hardcode English** in this phase (dojo-drop/the-cube/hoo-hee-how precedent); namespace comes at launch.
- Any game CSS namespaced under a root class (`.stuntman-chris .foo`), hoo-hee-how idiom.
- Sound prefs, if/when sound exists: `useUserPreferences()` only — no local mute state.
- Verification gate: `npx tsc --noEmit` (repo eslint is broken with a pre-existing flat-config crash — not ours to fix).
